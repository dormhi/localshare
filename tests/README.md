# Test strategy

Organize tests by component and level (unit, protocol, host integration, Android/device, security). Run `python3 -m unittest discover -s tests -p 'test_*.py'` for both platform-independent source-contract suites. `test_android_phase3_contract.py` covers the Android endpoint, identity, and permission boundary; `test_windows_phase3_contract.py` checks host source invariants. The Windows test file is currently uncommitted alongside its host source; sync both from the maintainer's working tree before running it in another checkout. These offline checks do not replace Android builds, Windows builds/runtime, or device tests. Windows runtime and tablet checks are tracked separately in [`docs/testing/phase-3-windows-checklist.md`](../docs/testing/phase-3-windows-checklist.md). Each test documents its prerequisites and whether it can run offline. Follow root `AGENTS.md`: relevant tests and fast static security checks before each commit; broader regression/security checks at phase completion. Never label unavailable Windows/device checks as passed.
